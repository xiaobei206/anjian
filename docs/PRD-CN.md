## 1. 产品定位

建立一款本地优先的 Windows 桌面自动化工具，保留经典按键精灵的工作流程：新建脚本、录制动作、编辑命令、运行/暂停/停止、查看日志。底层采用独立实现的 Lua 5.4 脚本引擎和本项目自己的命令 API。

这是独立产品实现。只借鉴用户熟悉的通用交互模式，不复制原厂闭源源码、未经授权素材或内部实现。

### 1.1 目标用户

- 希望通过录制键鼠动作完成重复操作的普通 Windows 用户。
- 能编写简单脚本、希望使用循环/条件/变量/函数的进阶用户。
- 需要在本地运行、可备份、可迁移自动化项目的个人用户。

### 1.2 核心价值

1. 低门槛：录制器和中文命令面板让用户不必从空白代码开始。
2. 可编程：Lua 提供成熟的流程控制和函数能力。
3. 可维护：动作、代码、资源和工程配置有明确结构。
4. 可控：运行状态可见，暂停/停止可靠，日志能定位错误。
5. 本地优先：不要求账户、云服务或持续联网。

## 2. 首版产品边界

### 2.1 P0 — 首版必须交付

**工程与脚本管理**
- 新建、打开、保存、另存为、关闭脚本。
- 工程/脚本列表、重命名、删除、资源文件夹。
- 关闭时检测未保存改动。
- Lua 文件可独立打开，不依赖数据库或云服务。

**代码编辑器**
- Lua 语法高亮、行号、自动缩进、括号匹配。
- 查找/替换、撤销/重做、多标签页。
- 命令自动补全、参数提示和中文说明。
- 运行错误可定位到脚本文件和行号。

**命令面板**
- 分类浏览、关键字搜索、双击插入。
- 命令详情显示用途、参数、返回值、示例和限制。
- 命令定义由单一注册中心提供，避免编辑器和文档分别维护。

**鼠标键盘控制**
- 鼠标移动、左/右/中键单击、双击、按下、释放、滚轮。
- 键盘按下、释放、单键点击、组合键和 Unicode 文本输入。
- 坐标使用虚拟桌面物理像素；允许副屏产生负坐标。
- 首版优先可靠控制当前交互桌面，不承诺所有应用/权限等级均可操作。

**录制器**
- 记录全局物理鼠标/键盘事件及时间戳。
- 录制开始、暂停、恢复、结束、取消。
- 动作列表查看、排序、插入、删除、复制和参数/延时编辑。
- 从动作列表生成 Lua 代码。
- 保存动作数据，异常退出后尽力恢复最近一次持久化状态。
- 显示事件溢出、权限问题或录制源不可用，不得静默丢失关键事件。

**运行控制**
- 运行、暂停、恢复、停止。
- 播放重复次数：默认 1；输入正整数表示完整脚本运行次数；0 表示无限循环。
- 每轮间隔：默认 2000 ms，可设置 0 至 600000 ms；只在一轮结束且下一轮开始前等待，最后一轮后不等待。
- 重复次数和每轮间隔是播放控制设置，与 Lua 脚本内部 Delay 完全独立，并在本机持久化。
- 全局热键采用经典按键精灵习惯：F10 启动、F11 暂停/继续、F12 中止；首个预览增量先固定默认组合，后续再开放自定义。
- 单实例脚本运行；同一个 Lua state 不允许并发调用。
- 长循环、延时和 API 调用边界响应停止请求。
- 停止/失败时释放由程序模拟按下且仍处于按下状态的键和鼠标按钮。

**日志与状态**
- 显示时间、级别、脚本、行号、消息。
- 明确显示 Idle / Validating / Running / Paused / Stopping / Completed / Cancelled / Failed。
- 日志可复制、清空和保存。

**便携发布**
- win-x64 自包含发布，ZIP 解压运行。
- 默认不要求管理员权限、不要求联网、不要求另装 .NET Runtime。
- 首版允许文件夹式发布，不强求单文件 EXE。

## 3. 明确不属于首版的范围

- 原版 Q 语言和旧版插件百分之百兼容。
- Android、iOS 或移动端控制。
- 云端账户、同步、脚本商城。
- 多机群控。
- 内核驱动、硬件级输入模拟、反作弊/安全软件绕过。
- 对受保护桌面、登录安全桌面或高完整性级别应用提供绕过能力。
- 默认以管理员身份启动。

## 4. 核心用户流程

### 流程 A：录制一个简单任务

1. 用户创建或打开工程。
2. 点击“录制”，执行物理鼠标和键盘操作。
3. 点击停止，录制器生成有序动作列表。
4. 用户在动作列表中修改坐标、按键、次数或延时。
5. 用户生成 Lua 代码，保存为 .lua 文件。
6. 用户运行并查看日志；必要时暂停或停止。

### 流程 B：编写脚本

1. 新建 Lua 脚本。
2. 通过命令面板插入命令或直接编写 Lua。
3. 编辑器提供补全、参数提示和中文帮助。
4. 运行前做语法/参数校验。
5. 运行时显示状态、日志和错误行号。
6. 用户停止或脚本自然结束，资源被清理。

### 流程 C：工程迁移

1. 用户复制整个工程目录。
2. 在另一台 Windows 电脑打开 .kpproj。
3. 相对路径资源仍可解析。
4. 如果运行环境缺少能力，软件给出具体提示。

## 5. 产品质量目标

- UI 不得因 Lua 长循环或延时而冻结。
- 停止请求在普通 Lua CPU 循环中的 P95 响应目标 ≤ 500 ms。
- Delay(60000) 等待期间停止目标 ≤ 300 ms。
- 单次录制队列溢出不得静默发生；必须报告且保留事件状态一致性。
- 运行/停止后不得留下本程序模拟按住的键或鼠标按钮。
- 工程保存失败不得悄悄覆盖旧文件。
- 至少完成连续 2 小时脚本运行稳定性测试。
- 所有性能指标须在记录测试环境、重复次数和 P95 计算方式后验收。

## 6. 易用性约束

- 中文界面为首版默认语言。
- 代码 API 使用英文稳定标识符，命令面板用中文说明。
- 默认快捷键需在应用失焦时仍可使用；后续开放自定义并检测冲突。
- 所有危险操作（删除工程、覆盖资源、重新生成代码）需明确提示。
- 新手可只使用录制器，高级用户可只使用 Lua 编辑器。

## 7. 首版完成定义（Definition of Done）

首版只有在以下条件全部满足时才算交付：
1. P0 功能逐项通过 ACCEPTANCE-TEST-CN.md。
2. Release 构建在干净 Windows 10/11 x64 环境启动成功。
3. 所有关键输入、录制、停止和数据保存测试通过。
4. 2 小时稳定性测试通过。
5. README、用户手册、依赖清单、开发日志和 SHA256 文件齐全。
6. 无未解释的 P0/P1 阻断问题。
7. 版本号、发布文件名、变更日志、测试报告一致。
