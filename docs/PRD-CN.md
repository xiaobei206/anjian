## 1. 产品定位

建立一款本地优先、可编程、可录制、可调试、可打包的 Windows 桌面自动化开发环境。普通用户可以通过录制器和命令面板完成任务；进阶用户可以使用 Lua 变量、表、条件、循环、函数和模块构建复杂流程；成熟脚本可以通过“小精灵”打包能力成为具有独立界面和参数配置的可交付应用。

目标是实现经典 PC 按键精灵核心使用场景的独立功能等价，而不是复制原厂闭源代码、内部实现、未经授权的素材或旧版语言运行时。脚本语言采用标准 Lua 5.4，不以旧版 Q 语言二进制/脚本完全兼容为承诺。

### 1.1 目标用户

- 不想手写代码、需要录制和重复执行日常桌面工作的普通用户。
- 能使用变量、条件、循环和函数，想写稳定自动化脚本的进阶用户。
- 需要查找窗口、相对坐标、图像/颜色识别、日志、参数和错误恢复的自动化作者。
- 希望将成熟脚本打包、配置参数并交给其他 Windows 用户使用的脚本作者。
- 需要维护脚本库、动作资源、插件和多任务运行配置的高级用户。

### 1.2 产品原则

1. **先可用，再可编程**：录制器、可视化动作列表与 Lua 编辑器提供不同入口。
2. **标准语言**：使用标准 Lua 5.4；产品专注自动化 API、IDE 和运行时。
3. **API 有契约**：每个公开函数必须有参数类型、默认值、限制、返回值、错误行为、示例和版本状态。
4. **单一事实来源**：API 注册表驱动编辑器补全、参数提示、命令面板、校验和函数手册生成。
5. **数据可迁移**：工程、动作、模板、参数和打包配置有 schema version、校验和迁移策略。
6. **停止可信**：停止、异常和退出均走统一清理，释放程序持有的按键/鼠标按钮；无法保证的情况要显示错误而不是谎报成功。
7. **能力边界透明**：前台输入、窗口消息、UI Automation、图像识别和 OCR 是不同能力，不宣称所有程序都支持后台操作。
8. **本地优先**：无账号、云端或持续联网依赖也可使用核心能力；网络 API 由脚本显式调用。
9. **可回滚、可验证**：小步直接集成到 main，测试和发布资产必须对应同一个版本。

## 2. 完整产品范围

下列能力都是正式产品目标。阶段次序见路线图；只有“明确不做”章节中的项目不属于本产品目标。

### 2.1 应用、工程与脚本管理

- 新建、打开、保存、另存为、重命名、复制、删除和关闭脚本。
- 多标签编辑、最近打开、脚本搜索、收藏、项目分组和工作区恢复。
- 工程文件与目录结构：脚本、录制动作、图片/字库/其他资源、参数定义、配置、插件引用和发布设置。
- 相对路径资源解析；工程复制或迁移到另一台电脑后仍能工作。
- 未保存修改提示、原子写入、备份和恢复、损坏文件诊断、schema 版本迁移。
- 工程级默认坐标模式、脚本运行参数、默认热键、日志策略和打包配置。
- 脚本模板、示例工程、常用函数库和可重复使用的子脚本。

### 2.2 完整脚本编辑器（IDE）

- Lua 语法高亮、行号、缩进辅助、括号匹配、代码折叠、查找/替换、撤销/重做、多标签和大文件编辑。
- 根据 API 注册表提供函数名补全、参数签名提示、中文悬浮文档、参数类型/默认值校验和示例插入。
- Lua 语法诊断、静态检查、运行前校验、错误文件/行号导航、调用堆栈展示。
- 断点、单步进入/越过/跳出、运行到光标、暂停/恢复、停止、变量监视和局部/全局变量查看。
- 断点命中状态、当前执行行标记、调用栈、运行时间和 API 调用耗时；调试器不得在 UI 线程执行脚本。
- 动作列表与代码视图相互关联。由录制器生成的代码区块拥有稳定 ID 与版本信息；手工修改后提示脱离同步，重生成前预览并确认。
- 可复制的错误报告，包含应用版本、脚本文件、行号、堆栈、相关日志和脱敏后的诊断元数据。

### 2.3 录制器与可视化动作列表

- 记录鼠标移动、各键鼠按下/释放、点击、双击、滚轮、按键组合和动作时间戳。
- 开始、暂停、继续、结束、取消录制；提供明确的录制状态提示与快捷键。
- 普通轨迹录制、只记录点击坐标、可调移动合并/采样阈值，以及必要时保留关键转向点。
- 动作列表提供插入、删除、复制、排序、分组、注释、启用/禁用、参数编辑、延时编辑、批量编辑和步骤试运行。
- 保存原始事件和结构化动作；事件队列溢出、无法配对的 Down/Up 或采集源故障必须显式告警。
- 从动作列表生成可读 Lua；维护生成区块 ID、schema、dirty/detached 状态和覆盖确认。
- 支持录制片段保存为可复用步骤；可以将选中动作转换为函数/子程序。
- 回放前展示目标窗口、坐标空间和风险设置；可设循环次数、轮间隔、失败策略和停止热键。
- 录制、运行和程序自身输入必须有防回灌措施，不能重复录入程序模拟的事件。

### 2.4 鼠标、键盘与文本输入

- 鼠标移动、单击、双击、按下/释放、滚轮、拖动、按住移动、相对移动，以及多键鼠标支持能力探测。
- 键盘单键、按下/释放、组合键、功能键、导航键、扩展键、数字小键盘、Unicode 文本输入。
- 可配置单击/双击按下时间、点击间隔、按键时长、动作间隔和随机延时。
- 统一输入状态追踪；失败、停止、暂停、工作进程退出时有明确的输入清理策略。
- 对输入法组合、Unicode、键盘布局和物理按键录制的差异作出说明，不把“文本输入”误称为对原始键盘事件的无损还原。
- 主要实现采用有文档的 Windows API，不使用内核驱动绕过权限边界。

### 2.5 完整坐标系统（必须交付）

坐标系统不再局限于绝对屏幕坐标。必须提供并清晰区分以下模式：

- **screen**：虚拟桌面物理像素坐标，支持副屏在左侧/上方导致的负坐标。
- **window**：相对目标窗口外框基准的坐标；必须明确标题栏和边框的计算规则。
- **client**：相对目标窗口客户区左上角的坐标，不将标题栏/边框混入客户区坐标。
- **anchor**：以窗口的左上、上中、右上、左中、中心、右中、左下、下中、右下等锚点为基准，并使用偏移量定位。
- **ratio/normalized**：以客户区宽高归一化的相对位置（例如 0 到 1），用于尺寸变化时保持相对位置。

必须提供屏幕/窗口/客户区之间的双向坐标换算；在高 DPI、混合缩放、多屏和窗口移动/缩放情况下验证坐标一致性。录制器应能记录所使用的目标窗口和坐标空间。默认保留现有 MoveTo(x, y) 的屏幕绝对坐标语义，新增窗口/客户区/锚点 API 或显式模式，避免静默改变旧脚本含义。

### 2.6 窗口与控件自动化

- 按标题、类名、进程名、进程 ID、可见性和匹配规则查找窗口；枚举窗口和子窗口。
- 获取窗口标题、类名、进程信息、外框矩形、客户区矩形、显示状态、前台/焦点状态。
- 激活、最小化、最大化、还原、显示/隐藏、置顶、移动、调整大小、按指定边/角/中心对齐窗口。
- 等待窗口出现、关闭、激活或状态变化；支持超时与取消。
- 客户区/屏幕坐标转换、鼠标指向窗口、坐标命中窗口和父子窗口关系查询。
- 对标准控件提供能力探测；在适用条件下读取/设置文本、选择项、勾选状态和触发控件操作。
- 为不支持直接控件访问的应用提供前台输入、图像识别或可选 UI Automation 适配，说明各后端的适用范围。
- 窗口引用在关闭后失效必须可检测；禁止使用过期句柄而误向另一个窗口输入。

### 2.7 前台与后台操作（分能力实现）

- 前台模式：使用系统鼠标键盘输入，目标窗口通常需要可见和处于适当交互状态。
- 后台模式：按能力提供窗口消息、标准控件/UI Automation 或经过验证的专用后端；每种模式明确支持的窗口类型、鼠标/键盘/文本/图像能力。
- 自动模式：可探测并选择可用后端；不支持时返回明确错误或经用户允许切换前台模式，不静默假装成功。
- 窗口绑定/解绑、后台操作能力报告、输入结果与失败原因可查询。
- 后台截图与前台屏幕截图分别定义；不把遮挡窗口、硬件加速窗口或受保护内容的截图成功作为默认保证。
- 不尝试绕过 UAC 安全桌面、UIPI、反作弊、DRM、安全软件或其他访问控制。后台能力的开发以公开、可审计的 Windows API 为边界。

### 2.8 屏幕、截图、找图、找色与 OCR

- 全屏/指定窗口/客户区/自定义区域截图；截图保存文件或在脚本中短时缓存，明确释放内存资源。
- 读取像素颜色、颜色比较、颜色差值、RGB/十六进制转换、多点找色、颜色块/区域颜色计数。
- 模板找图：指定区域、相似度阈值、灰度/缩放策略、多个结果、结果排序、结果坐标、超时和查找失败行为。
- 图像资源管理：脚本级 .images.json 清单与同名 .assets/ 目录；支持 PNG 导入、列表、预览、命名、裁剪、透明区域处理、相似度标注、相对路径与 schema/尺寸/文件大小/SHA-256 校验；静态 LoadImage 字面依赖可检查，动态路径明确标注无法静态解析；脚本重命名/复制/删除同步处理清单和资产目录。UI 仅缓存不可变像素模型，GDI Bitmap 只在加载/绘制时临时创建并释放。
- OCR：支持指定区域、本地图片或截图识字；语言/模型包可管理；返回全文、逐行文本、置信度、矩形和多边形边界框。文本查找支持精确/包含匹配和置信度阈值；等待文本支持超时、轮询、暂停与停止。核心识别必须离线可用，模型由用户明确下载/安装，脚本执行期间不得静默联网。模型包记录来源、版本、许可证、SHA-256 和缓存位置。
- 支持等待指定图像/颜色出现或消失，连续多次确认，避免单帧误判。
- 提供可选视觉调试层：截图区域框、找色/找图/颜色块命中位置、相似度、RGB/十六进制数值和检测耗时；覆盖层置顶、透明、点击穿透，关闭后不拦截输入，并通过 Windows Display Affinity 尝试从截图中排除。
- 对图像引擎和 OCR 组件记录许可证、运行平台、离线模型/数据文件、依赖体积和性能；目标能力不能依赖未经确认的云服务。主 UI 不得执行同步 OCR 推理；可能阻塞的引擎调用必须在可被停止的独立 Worker 内运行。
- 所有视觉函数都定义截图区域使用何种坐标空间；截图失败、权限限制或超时必须有独立返回状态。

### 2.9 参数、变量、数据与流程控制

- 使用 Lua 5.4 原生变量、局部变量、表、条件、循环、函数、闭包、模块和错误处理。
- 提供脚本参数声明系统：参数名、中文标签、类型、必填、默认值、最小/最大值、选项、说明、验证规则和排序。
- 参数类型至少包括文本、整数/小数、布尔、下拉/单选、多选、文件路径、目录路径、热键和可选颜色值。
- 小精灵参数 UI 将用户填写值安全、明确地传入脚本；区分参数输入和脚本运行中的变量。
- 参数校验在启动前完成；错误需指出字段和规则。配置可保存、恢复默认、导入/导出，敏感输入默认不写入普通日志。
- 文件/目录参数的相对路径以脚本所在目录为基准；用户配置可保留相对路径以便移动工程，传入 Lua 的运行时路径应解析为绝对路径。参数表入口只读，不能将用户输入拼接执行为 Lua 代码。
- 提供可复用函数库、子脚本调用、模块引用、返回值与错误传播约定。
- 可选调试变量窗显示局部/全局变量、表结构和监视表达式；避免显示私密内容时自动写入诊断日志。

### 2.10 稳定性、定时与多任务运行

- 明确的运行状态机：Idle、Validating、Running、Paused、Stopping、Completed、Cancelled、Failed。
- 运行、暂停、继续、停止、重启，统一停止令牌、Lua 指令检查点与可取消等待。
- 单脚本多轮播放、轮间隔、失败后停止/重试/继续的可配置策略。
- 多脚本工程、子脚本/函数库和受控的多实例运行；每个实例拥有独立 Lua state、日志、参数和输入资源管理。
- 定时启动、延迟启动、循环定时任务和可选任务编排；界面需清楚显示任务状态和下次启动时间。
- 脚本超时、连续失败限制、异常通知、日志轮转与自动清理。
- 应用崩溃或 worker 退出后不遗留本程序模拟按下的键鼠；能恢复到可操作状态并保留必要诊断信息。

### 2.11 其他自动化 API

为覆盖桌面自动化常见需求，提供边界清晰的内置 API：

- 时间、随机数、字符串、数学、表、编码和 JSON 数据处理。
- 文件/目录读写、存在性检查、遍历、复制、移动、重命名、创建目录和受控临时文件。
- 剪贴板读取/写入、简单消息框、输入框、确认框、通知/声音和用户可见交互。
- 启动/查询/等待外部应用与进程，获取受允许范围内的进程信息；关闭进程需显式确认策略并处理权限失败。
- HTTP/HTTPS 请求、超时、请求头、状态码、文本/JSON 响应和文件下载/上传；网络行为由脚本显式使用，默认无后台联网。
- 环境信息、屏幕/显示器信息、路径、应用版本、运行实例信息和诊断信息。
- API 必须尊重路径边界、超时、错误处理和用户权限；不暴露任意 .NET 反射或不受控 Shell 执行作为默认脚本能力。

**实现状态注记（main 开发版，2026-11-13；不缩减冻结范围）：** M12-02 已落地 13 项受控文件 API：ReadTextFile、WriteTextFile、AppendTextFile、FileExists、DirectoryExists、ListFiles、ListDirectories、CreateDirectory、CopyFile、MoveFile、RenameFile、CreateTempFile、CreateTempDirectory。Worker 与主进程 IPC 双层检查每次 Grant；Windows no-follow 句柄拒绝 reparse point/符号链接和多硬链接文件。文本严格 UTF-8、4 MiB 上限；目录枚举非递归、最多 1000 项；Copy/跨卷 Move 限 64 MiB，复制到目标同目录临时文件后 flush、SHA-256 校验再提交；同卷 Move/Rename 使用句柄级重命名。临时文件/目录由调用者明确指定已批准写入目录，不自动使用系统 TEMP。仅支持普通文件，目录复制/移动/重命名不在本批范围。M12-07 已在 main 实现剪贴板/对话框 API（GetClipboardText、SetClipboardText、MessageBox、InputBox、Confirm），权限默认拒绝并由 Worker/主进程双层校验。M12-08 已实现受控进程 API StartProcess/WaitProcess/GetProcessInfo：精确 EXE 路径逐次批准、ArgumentList 安全传参、仅本次运行随机句柄、等待超时/Pause/Stop 取消与退出码查询；不开放 Shell 或任意 PID/进程终止。M12-09 已在 main 实现受控 HttpRequest(url, options?)：复用 httpHosts/httpMethods/allowInsecureHttp 逐次授权，HTTPS 默认、HTTP 单独批准、每跳重定向重新授权、1 MiB 请求体/4 MiB 响应体、默认 30 秒超时与 Stop 取消。当前 main API registry 为 1.2 / 103 项；M12-08 Windows Actions run 43414530292 的 152/152 Core tests、0 warnings/errors 和自包含包 smoke 全 PASS；M12-09 Windows Actions run 43427860126 全 PASS（161/161 Core tests、0 warnings/0 errors、103 项 API handbook、自包含包与 Sprite/Worker smoke）。插件仍待后续 M12 子任务。该开发版未改变已发布的 v0.1.0-preview.4；M14 Windows 10/11 桌面实机验收仍 NOT RUN。

### 2.12 插件与扩展命令

插件目录/ZIP 的 schema v1、版本兼容、闭合文件列表、SHA-256 与三方权限交集由本地插件包格式规格 [PLUGIN-MANIFEST-CN.md](PLUGIN-MANIFEST-CN.md) 冻结。M12-10 已在 main 开发版实现本地校验、安装、启停/卸载和独立 Worker 运行；第三方动态注册 Lua API/命令面板与 M12-11 小精灵 sidecar 接入仍是后续任务，真实 Windows 桌面交互统一留 M14。


- 提供正式的本地插件/命令包机制，可导入、启用、停用、升级和卸载。
- 每个插件带 manifest：名称、版本、作者、说明、兼容 API 版本、文件清单、权限声明和入口点。
- 插件 API、生命周期、日志、错误传播和资源路径有稳定契约；异常插件不得拖垮整个 UI。
- 安装/运行前显示插件来源与所需能力；支持禁用第三方扩展和查看校验信息。
- 插件可提供 Lua 函数、编辑器提示、命令面板项目和帮助页面；必须纳入同一 API 注册及文档生成机制。
- 不以第三方插件市场、账号系统或云分发为核心依赖；本地 ZIP/目录分发即可完成首个扩展系统。

### 2.13 “小精灵”独立打包与发布（必须交付）

这是完整产品的核心交付能力，不能只保存 Lua 文件或把普通主程序压缩后称为小精灵。

- 选择一个或多个脚本入口，自动收集工程依赖、图片模板、字库、配置和必需资源。
- 生成可独立运行的应用包；至少提供便携文件夹包与带启动入口的独立 EXE/发布包。技术验证允许先以自包含目录为基础，但用户使用时不得要求安装开发工具或手动配置 Lua。
- 每个包拥有独立产品名、版本号、图标、说明、作者/版权信息和可选关于页面。
- 支持通过可视化定义生成用户参数界面：文本框、数字框、复选框、下拉/单选、文件/目录选择、热键等；参数有默认值和范围校验。
- 用户界面至少提供启动、暂停/继续、停止、运行状态、错误提示和按配置显示的日志；作者可以选择简洁模式或高级日志模式。
- 配置循环次数、轮间隔、启动热键、自动启动行为、单实例策略、失败重试和退出时清理规则。
- 脚本运行与开发环境隔离；小精灵不要求用户访问工程源码或安装完整开发 IDE。
- 打包前执行入口/参数/资源/依赖校验，显示缺失文件和兼容性错误。
- 输出 package manifest、版本、文件清单、SHA256、API/运行时最低版本和构建日志；用户能验证包是否损坏。
- 用户配置与包文件分离；升级不能静默覆盖用户数据；配置 schema 变化需迁移或备份。
- 可选发布说明、安装/卸载说明、版本升级检测机制；更新检查默认可关闭，不强制云服务。
- 如果技术上不能安全单文件化，界面必须明确显示文件夹包或 EXE 启动器实际需要的伴随文件，不宣传虚假的“真正单文件”。

### 2.14 函数/参数说明书与帮助系统（必须交付）

- 仓库中维护正式中文《函数与参数参考手册》，当前文件为 docs/FUNCTION-REFERENCE-CN.md。
- 每个可供用户调用的函数至少包含：函数名称、所属类别、函数签名、说明、每个参数的名称/类型/必填性/默认值/取值范围/单位、返回值结构、可能错误、停止/暂停行为、坐标语义、副作用、版本/状态、最小示例和常见陷阱。
- 公开 API 的状态必须区分“当前已实现并测试”“已实现但实机待验收”“计划设计中”“弃用”，不得混写。
- API 注册表是唯一机器可读来源，自动生成 IDE 补全、参数提示、命令面板和函数手册；测试检查生成文档与注册表一致。
- 正式发行包包含离线使用说明和函数参考（Markdown 与可阅读的离线 HTML；若生成链路尚未建立，先将 Markdown 纳入包并记录 HTML 为明确的交付任务）。
- 每次新增/修改公开函数，必须同步更新签名、兼容性、示例、自动化测试和变更日志；破坏性变更需要版本迁移说明。
- Lua 标准库也提供合适的入门索引；第三方插件函数的文档由插件 manifest/注册描述生成并标识来源。

## 3. 用户核心流程

### 流程 A：录制并整理动作
创建工程 → 开始录制 → 暂停/继续/结束 → 在动作列表编辑坐标、延时和按键 → 选择坐标空间与目标窗口 → 生成 Lua → 预览并保存 → 运行、调试和查看日志。

### 流程 B：编写可维护脚本
新建 Lua → 通过补全/命令面板调用函数 → 查看参数提示与手册 → 运行前检查 → 设置断点/单步调试 → 检查变量与调用栈 → 修正错误并保存到工程。

### 流程 C：编写窗口/视觉自动化
定位目标窗口 → 检查窗口/控件/截图能力 → 选择屏幕、窗口或客户区坐标 → 等待窗口/图像/颜色 → 执行操作 → 根据返回状态或超时分支处理失败。

### 流程 D：发布小精灵
选择入口脚本 → 定义用户参数表单与运行选项 → 自动收集资源依赖 → 构建并校验 → 测试生成的独立包 → 输出可交付文件、说明书和 SHA256 → 在干净 Windows 环境验证。

### 流程 E：安装扩展 API
导入插件包 → 审阅权限、来源和版本 → 启用扩展 → 编辑器显示扩展函数提示 → 在脚本中调用 → 文档与日志清楚标出扩展来源与错误。

## 4. 兼容性和明确不做的事项

### 必须做到
- Windows 10 / Windows 11 x64 桌面版本。
- 经典 PC 自动化的功能等价：键鼠输入、录制、脚本编辑/调试、变量/流程控制、窗口与坐标、图色识别、用户界面、扩展命令和小精灵式发布。
- 便携运行、自包含部署、清晰参数契约和完整离线帮助。
- 对公开 API 的版本化和兼容性管理。

### 不作为目标
- 旧版 Q 语言/旧插件二进制的百分之百兼容；可另行提供有范围限制的转换器，但不得妨碍 Lua 主线。
- Android/iOS 自动化、手机群控和跨设备云控制。
- 云账号、脚本商城、云端执行服务或强制在线授权。
- 内核驱动、提权常驻、反作弊/安全软件绕过、访问控制规避。
- 对任意第三方应用承诺通用后台输入成功；只能对经过验证的窗口/控件类型声明支持。
- 远程群控/多机调度不是桌面版 1.0 必需能力。

## 5. 质量、可靠性与安全目标

- UI 不得因脚本长循环、等待、图像搜索或网络请求而冻结。
- 长等待和运行中 API 可响应统一停止请求；CPU 密集循环通过 Lua 指令检查点检测停止。
- 停止、异常、脚本进程退出和程序正常退出均执行统一键鼠输入清理。
- P95 停止响应目标：普通 Lua CPU 循环不超过 500ms；Delay(60000) 等待不超过 300ms。测量必须记录 30 次以上样本、环境和 P95 计算方式。
- 事件队列溢出必须显式报告；不得静默丢失关键 Down/Up。
- 文件保存采用原子写入或可恢复策略；打包时校验依赖完整性。
- 支持至少 2 小时连续稳定性测试、100 次运行/停止回归、混合 DPI/多显示器与负坐标验证。
- 对权限、窗口绑定、后台后端、图像截取和网络错误提供可理解的诊断。
- 默认普通用户权限启动，不要求联网；明确拒绝绕过受保护桌面和系统安全边界。
